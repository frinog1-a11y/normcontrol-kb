# Между строк чертежа

**Личный справочник нормоконтролёра.** База знаний по ЕСКД: типовые ошибки, конспекты ГОСТов, чек-листы проверки и примеры оформления. Публикуется как статический сайт с поиском, двусторонними ссылками и графом связей.

- Сайт: <https://frinog1-a11y.github.io/normcontrol-kb/>
- Репозиторий: <https://github.com/frinog1-a11y/normcontrol-kb>

## Проблема

Нормоконтролёр ежедневно проверяет десятки чертежей и документов. Каждая ошибка требует поиска ГОСТа, проверки смежных ошибок и сверки с примерами. Без единой базы это занимает часы, а одни и те же замечания повторяются из документа в документ.

## Решение

Единая база знаний в **Obsidian** с публикацией на **GitHub Pages** через **Quartz**. Заметки связаны двусторонними ссылками: из ошибки — к ГОСТу, из ГОСТа — к списку ошибок по нему, из типа документа — к чек-листу проверки.

### Что уже есть в базе

| Раздел | Содержимое |
| --- | --- |
| Ошибки | 24 карточки в 7 категориях: чертёж общие, основная надпись, спецификация, сборочный чертёж, схемы, обозначения, электронные документы |
| ГОСТы | 46 конспектов: действующие ГОСТ Р (2023–2024), действующие ГОСТ, стандарты БАС 2026, устаревшие редакции |
| Документы | 29 типов в 5 категориях (графические, текстовые, схемы, эксплуатационные, ремонтные) с чек-листами проверки |
| Шаблоны | заготовки заметок об ошибке, документе и ГОСТе |

### Ключевые особенности

- **Двусторонние ссылки**: ошибка ↔ ГОСТ ↔ документ. Проверяется автоматически: 29 из 29 документов ссылаются на ошибки, 46 из 46 ГОСТов — на ошибки по ним.
- **Единая схема карточки ошибки**: категория, ГОСТ, документ, «как выглядит / как правильно», примеры, пункт ГОСТа, смежные ошибки.
- **Граф связей** в правой панели: узлы окрашены по категориям, размер зависит от числа связей, подписи — у крупных узлов, мягкая кластеризация по разделам.
- **Поиск по всей базе**, светлая и тёмная темы, адаптивная вёрстка, кнопка «наверх».
- **Доступ через браузер**: софт на рабочем ПК не нужен, есть режим правки прямо на GitHub и веб-редактор базы.
- **Автоматическая публикация**: push → GitHub Actions собирает сайт → GitHub Pages.

## Как это сделано

1. **Контент** — Markdown с frontmatter (`title`, `description`, `теги`/`tags`) и Obsidian-ссылками `[[заметка]]`. Заметки лежат папками по разделам, у каждой папки — `_index.md`.
2. **Сайт** — Quartz 4. Кастомизированы: тема и палитра (`quartz.config.ts`), раскладка и граф (`quartz.layout.ts`), стили (`quartz/styles/custom.scss`), скрипт графа (`quartz/components/scripts/graph.inline.ts`), компоненты «Править на GitHub» и «Наверх».
3. **Публикация** — GitHub Actions (`.github/workflows/deploy.yml`): сборка Quartz и деплой на Pages. Отдельная задача превращает issue с телефона в заметку базы.
4. **Проверки** — `npx tsc --noEmit`, `npx prettier --check` и скриптовый аудит: разрешимость ссылок, дубли и опечатки тегов, метаданные, двусторонние связи.

## Технологии

- **Obsidian** — редактор Markdown
- **Quartz 4** — генератор статических сайтов
- **GitHub Pages** — хостинг
- **GitHub Actions** — CI/CD
- **Node.js 22+**, TypeScript, SCSS, D3 + Pixi (граф связей)

Важно: ядро Quartz почти не правилось — все изменения оформлены как помеченные патчи `PATCH (normcontrol-kb)`, чтобы обновление Quartz не ломало проект.

## Структура базы

```
content/
├── index.md                главная страница
├── 00_Инбокс.md            быстрые записи в течение дня
├── 01_Вопросы.md           открытые вопросы
├── 02_Ошибки/              каталог типовых ошибок: 7 категорий, 24 карточки
├── 03_ГОСТы/               конспекты стандартов: 46 заметок
├── 04_Документы/           чек-листы по типам документов: 5 категорий, 29 типов
├── 05_Примеры/             сканы «плохо/хорошо» (папки Плохо/ и Хорошо/)
├── 05_Элементы_оформления/ основная надпись, рамка, форматы
└── 99_Шаблоны/             шаблоны заметок
```

## Как запустить локально

```bash
git clone https://github.com/frinog1-a11y/normcontrol-kb.git
cd normcontrol-kb
npm install
npx quartz build --serve
```

Сайт откроется на <http://localhost:8080>. Собрать статику без сервера — ```npx quartz build``` (результат в папке `public/`).

Проверки перед публикацией:

```bash
npx tsc --noEmit
npx prettier --check .
```

## Как добавить материал

1. Откройте как хранилище (vault) папку `content` — там только заметки, без кода Quartz и `node_modules`, поэтому поиск и граф не засоряются лишним.
2. Быстрая запись — в `00_Инбокс.md`, разбор — раз в неделю.
3. Новая ошибка — по шаблону `99_Шаблоны/Шаблон_ошибки.md`, новый стандарт — `Шаблон_ГОСТа.md`, новый документ — `Шаблон_документа.md`.
4. В карточке ошибки заполните: категорию, ГОСТ, **документ**, «как выглядит / как правильно», пункт ГОСТа и смежные ошибки.
5. Связывайте заметки ссылками `[[Имя_заметки]]`: без связей заметка остаётся в стороне от графа и её никто не найдёт.

## Как опубликовать изменения

```bash
git add .
git commit -m "Обновление базы"
git push
```

GitHub Actions сам соберёт сайт и выложит его на GitHub Pages (2–5 минут). Статус сборки — вкладка **Actions** в репозитории.

## Важно про данные

База публичная. Перед добавлением материалов удаляйте персональные данные, названия организаций, подписи и всё, что относится к реальным заказам. Проверяйте это при добавлении примеров в `05_Примеры/`.
